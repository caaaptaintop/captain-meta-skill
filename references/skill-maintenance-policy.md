# Skill 维护规范

本规范由 Captain 维护，供所有 Agent 在创建、持久修改或更新技能时按需读取。普通执行只加载目标 `SKILL.md` 和存在的 `local-data/ADAPTATION.md`；无需为每次使用加载整个 Captain。用户指令、已有授权和安全规则优先，不因本规范重复索取批准。

## 先分类，再确定写入位置

| 类型 | 判断依据 | 写入与更新方式 |
| --- | --- | --- |
| `local` 本机配置 | 换一台机器或账号便失效的路径、依赖环境、偏好、状态、缓存、私有素材 | 优先使用技能已有的外部配置入口；需要技能内本机资源时才创建 `local-data/` 和 `ADAPTATION.md`。不把这些值写进上游源码。 |
| `custom` 功能定制 | 改变路由、能力、流程或实现，可在别的机器复用 | 在用户已授权范围内修改 `SKILL.md`、`scripts/`、`references/` 或可分发的适配代码；保留真实来源、基线和差异。不能将定制版当作无差异原版覆盖更新。 |
| `update` 上游更新 | 从已登记的作者版本升级到另一个已核验版本 | 先核对本机配置及定制差异，再隔离合并、迁移和验收；保留现有数据、适配、权限和链接。管理器的更新按钮不能代替此核对。 |

一次任务可以包含多类改动，分别列明文件边界。例如增加新检索平台属于功能定制，运行平台所用的本机路径属于配置。不要将所有新代码藏入 `local-data/`，归属见下表。已有混合实现不因本规范自动迁移。

### 按来源决定脚本放哪

动手前先查来源（`source_type` 和 `source_ref`），不凭目录名猜；本机查询命令写在 Captain 的 `local-data/ADAPTATION.md`。`source_ref` 指向用户自己的仓库或账号时按自建处理：改动直接提交到该仓库并发版，再由管理器更新回本机，不长期以本机补丁形式叠加。只有第三方作者的仓库才算「有上游」。

| 来源 | 只给本机用的辅助脚本 | 可复用的功能代码 | 本机配置 |
| --- | --- | --- | --- |
| 自建（`source_type=local`，或 `source_ref` 是用户自己的仓库） | 技能 `scripts/` | 技能 `scripts/` | `local-data/` |
| 第三方上游（他人仓库） | `local-data/scripts/`，不写进上游 `scripts/`，以免更新时被覆盖 | 按 `custom` 进 `scripts/`，保存补丁与基线，更新时先比对再隔离重放；或提给作者 | `local-data/` |

`SKILL.md` 只写规则和脚本路径；命令细节、参数和可复用步骤放进脚本开头的用法说明。`ADAPTATION.md` 只记本机事实、核验和恢复，不复制流程。

## 首次需要本机资源时

1. 先检查目标已有的配置参数、环境入口和适配说明，复用有效路径，不制造第二份配置。
2. 没有相关本机资源就不创建目录。需要技能内资源时，由执行 Agent 创建最小的 `local-data/`，并立即建立 `local-data/ADAPTATION.md`；它是操作要求，不是管理器自动重定向功能。
3. 适配说明仅记录该技能的实际用途、入口、路径、依赖、配置位置、来源/定制状态、核验与恢复方法。相对路径基于说明所在目录；上游相对路径仍基于技能根目录。不复制整份通用规范。
4. 凭据正文使用系统钥匙串或已有受限配置；说明里只写位置和使用方法。确需新建私有配置时限制权限，报告只显示存在性或脱敏结果。不要在源码、示例、命令参数、补丁或日志里保存秘密。
5. 只给本机用的辅助脚本按上表放置；缓存、虚拟环境、临时状态与私有运行资料在 `local-data/` 或明确的外部位置；业务交付件在用户项目/指定输出目录。可分发的适配实现可用 `adapters/`，但该名称本身不代表可公开。
6. 若脚本硬编码写回技能源码，先查真实写入点。优先用已有配置入口；需要修改脚本时按 `custom` 处理，不能只建目录便声称已改道。

## 修改前

- 明确目标实体与当前部署入口，检查上游说明和本机适配，列出本次允许改动的文件。
- 备份受影响的源文件与本机资料；记录真实作者来源、分支/子目录、版本或提交，以及当前安装快照。未知基线如实标为未知，以快照留证，不猜提交。
- 功能定制保存可复现差异（Git 提交/补丁及新增文件）和验证、回退方法；保存在可持续维护的源码仓库或受保护本机位置。已有明确授权持续有效；只对新增高风险范围另行确认。
- 通过 Yao 的现有实现流程修改；`adapt-apply` 的目标清单、基线哈希与回退机制可复用。清单是任务边界记录，不另设重复的人为批准环节。

## 修改后按分类核验

- `local`：确认实际脚本读写入口已使用本机配置；上游源码未被意外改动，适配说明存在，私有资料不进入分发包。
- `custom`：确认源码差异仅涉及授权文件、原有配置及数据保留，运行原失败场景和最接近的回归场景；在适配说明中指向来源、基线、差异及恢复记录。登记来源保持真实，不能为隐藏差异伪造最新上游提交。
- `update`：先比对旧上游、本机定制和新上游。在隔离副本完成合并及所需的数据迁移；核对文件内容、权限、链接与必要的外部依赖，再替换正式实体。冲突只暂停受影响技能，其他独立工作继续。失败恢复该次备份，不能用旧整库覆盖后续业务数据。
- 发布、打包或同步前，检查实际文件清单和归档内容；排除凭据、`local-data/`、私有素材/状态、虚拟环境和运行日志。`.gitignore`、目录名与更新保留机制都不能单独证明未泄露；`adapters/` 中也可能有本机资料，须按内容判定。
- 报告区分源码状态、部署状态和证据等级；不把静态检查或模拟当作真实业务验收。

## Yao 文件边界核验

已有更新前副本时，可用同一 Yao 入口比对实际树，而非仅相信声明的变更列表：

```bash
python3 /path/to/captain/scripts/yao.py maintenance-check /path/to/skill \
  --before /path/to/before-copy --kind custom \
  --source-ref https://example.org/author/skill.git --base-revision KNOWN_BASE \
  --allow SKILL.md --allow scripts/feature.py \
  --allow local-data/ADAPTATION.md --output-json /path/to/private-task/check.json
```

`--allow` 是精确相对文件路径，不是通配符。`local` 只允许 `local-data/` 内的已列文件；`custom` 要记录来源与基线；`update` 还要求原 `local-data/`、`adapters/` 保持不变。确需迁移这些内容时，先保留原副本，再将获授权的迁移作为单独的 `custom` 步骤核验，另验迁移前后数据等价。

此核验只比较两份树的文件内容哈希、类型、POSIX 权限与链接目标，不创建目录、不执行更新、不验证授权、不拦截其他程序写入，也不跟随链接核验外部数据。`.git/` 与 `__pycache__/` 不比较。ACL、扩展属性、外部链接指向的数据及业务正确性仍按实际平台和风险另验。只读任务不创建副本或运行写入检查；新建技能按实际新增范围与原有空目录比对，或直接使用已有创建验收。

## 规则分工

- Captain 本文件是主规范；其创建、演进和更新流程引用本文件。
- 全局 Agent 规则只保留加载和修改前读取本规范的短入口，由本机共用规则管理工具同步；本机为 Magpie。项目规则不复制主规范。
- 各技能的 `ADAPTATION.md` 仅保存具体本机事实。插件/外部应用管理的技能沿用宿主安装与升级入口；不能直接改缓存副本并假定修改永久有效。
- 更新器负责已实现的文件保留，Agent 负责分类、配置入口、定制合并与验收。没有实际实现和验证，不宣称自动隔离、自动迁移或不可修改。
